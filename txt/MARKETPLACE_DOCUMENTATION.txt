## Step 1: Marketplace Homepage (index.blade.php)
**Route:** `GET /marketplace` → `MarketPlaceController@index()`
**Layout:** `@extends('layouts.app')` (uses the main app layout)
**Controller file:** `C:\laragon\www\new-youtube\app\Http\Controllers\MarketPlaceController.php`

### How the controller prepares data (lines 26-103):

1. **Step 1A — Parse request filters**: The `index()` method reads three query parameters: `type` (role profession like "Actor", "Director"), `location` (Indian state), and `search` (keyword). These come from the search/filter form on the page.

2. **Step 1B — Build featured query**: The method creates a query called `$featuredQuery` on the `MarketPlace` model for profiles where `status = 1` AND either:
   - `is_featured = true` (manually marked as featured by admin), OR
   - Has an active subscription (where `end_date > now()` OR `end_date IS NULL` for lifetime) AND that subscription's plan has `is_featured_plan = true`
   - This means featured profiles are a combination of admin-curated featured profiles AND creators who have purchased a featured plan.

3. **Step 1C — Build regular query**: A separate `$regularQuery` fetches active profiles where `is_featured = false`. This ensures regular profiles don't appear in the featured section and vice versa.

4. **Step 1D — Apply filters**: If the user selects a role type (e.g., "Actor"), both queries are filtered to only show profiles of that type. Similarly for location. For search, the method checks across name, type, location, skills, business_name, and email fields using LIKE %keyword% queries.

5. **Step 1E — Limit results**: Featured profiles are limited to 8 random picks. Regular profiles are limited to 24 random picks. This keeps the homepage fast-loading.

6. **Step 1F — Check logged-in creator**: The method checks `session('marketplace_user_id')`. If a creator is logged in, it fetches their full profile record and checks if they have an active subscription (for displaying the active plan badge). This data is passed to the view as `$talent` and `$activeSubscription`.

7. **Step 1G — Fetch gallery items**: The latest 8 gallery images from active creators are pulled for the gallery showcase section.

8. **Step 1H — Calculate stats**: Three numbers are computed:
   - `$stats['profiles']` = count of all active profiles
   - `$stats['featured']` = count of featured active profiles
   - `$stats['services']` = count of all services across all creators

9. **Step 1I — Load plans**: All `UserPlan` records are fetched (Silver, Gold, Platinum, Diamond Pro).

10. **Step 1J — Return the view**: All data is compacted and sent to `frontend.marketplace.index`.

## Step 2: All Profiles Page (all.blade.php)
**Route:** `GET /marketplace/all` → `MarketPlaceController@all()`
**Layout:** `@extends('layouts.app')`

### Controller Logic (lines 108-168):

1. Reads `type`, `search`, and `filter` query parameters.

2. Starts with a base query: `MarketPlace::where('status', 1)` — only active profiles.

3. **Type filter**: If a type is specified, filters by exact match on the `type` column.

4. **Featured filter**: If `filter == 'featured'`, applies the same featured logic as the homepage (is_featured=true OR has active featured-plan subscription).

5. **Search filter**: If a search term is present, applies LIKE queries on name, type, location, skills, business_name, email.

6. **Sorting**: If `filter == 'latest'`, orders by `created_at DESC`. Otherwise defaults to ordering by active subscription count (featured first) then newest.

7. **Pagination**: 24 profiles per page.

8. **AJAX support**: If the request has `X-Requested-With: XMLHttpRequest` header, returns JSON with rendered HTML for the profiles grid and pagination links. The frontend JavaScript uses this to update the DOM without page reload.

### Frontend Alpine.js Logic:

The page uses a comprehensive Alpine.js component (`x-data`) with:
- **State variables**: `loading`, `filter`, `type`, `search`, `showDropdown`
- **`fetchProfiles()`**: Builds a URL with current filter/type/search params, calls `window.history.pushState` to update the URL, fetches JSON from server, swaps `innerHTML` of the profiles container and pagination container
- **`setFilter(val)`**: Sets the filter (featured/latest), clears type, closes dropdown, fetches
- **`setType(val)`**: Sets the type filter, clears filter, closes dropdown, fetches
- **`resetFilters()`**: Clears all filters and fetches
- **`getActiveLabel()`**: Returns the current active filter label for display on the filter button

### User experience flow:

1. User lands on the page and sees a header with "All Profiles" title and "Back to Marketplace" link.

2. Below the header is a sticky filter bar that stays visible while scrolling:
   - Left: A filter button using Laravel Jetstream's `<x-dropdown>` component. Clicking opens a dropdown with:
     - "All Profiles" (default)
     - "Featured Only"
     - A divider
     - Individual role filters (Actor, Actress, Director, etc.) in a scrollable list (max-height 256px with custom scrollbar)
   - Right: A search input with debounced input (500ms delay) that triggers `fetchProfiles()` as the user types. A loading spinner replaces the search icon during AJAX requests.

3. The profiles grid shows 24 profiles at a time with pagination below. During loading, a blur/grayscale overlay with reduced opacity provides visual feedback.

4. Pagination links load new pages via normal HTTP requests (not AJAX).

## Step 5: Public Creator Portfolio (portfolio.blade.php)
**Route:** `GET /m/{slug}` → `MarketPlaceController@portfolio($slug)`
**Layout:** `@extends('layouts.app')`

This is the most complex marketplace view (~990 lines). It is a full public portfolio/profile page for a creator.

### Controller Logic (lines 201-218):

1. Fetches a single marketplace profile by its `slug` field, eager-loading:
   - `galleries` (portfolio gallery images)
   - `services` (service offerings)
   - `portfolios.images` (portfolio items with their images)

2. If the current visitor is authenticated (logged into the main platform), fetches all messages between this user and the marketplace profile for the live chat feature.

3. Returns the portfolio view with marketplace, messages, and page title.

### Frontend subscription gating logic:

At the top of the view, PHP logic determines what the visitor can see:
```php
$hasSubscription = auth()->check() && (
    auth()->user()->purchasedPlans()->where('expired_date', '>', now())->exists()
);
$isOwner = session('marketplace_user_id') == $marketplace->id;
$canView = $hasSubscription || $isOwner;
```
- **$hasSubscription**: The logged-in user has an active subscription plan
- **$isOwner**: The currently logged-in marketplace creator is viewing their own profile
- **$canView**: If either condition is true, premium content (contact details, messaging) is unlocked

## Step 8: Creator Registration (register.blade.php)
**Route:** `GET /marketplace/register` → `MarketPlaceController@showRegistrationForm()`
**Layout:** `@extends('layouts.app'`) with custom CSS overrides

### Controller Registration Logic (lines 369-436):

1. **Step 1 — Validate input**: Validates name, email (unique in market_places table, RFC DNS check), phone number (unique), password (min 8 chars, must have uppercase, lowercase, number, symbol — all confirmed), location, type (role), years_of_experience, bio, skills, URLs, business details, and both terms agreements.

2. **Step 2 — Handle business type**: If `business_type === 'other'`, the custom value from `other_business_type` is used instead.

3. **Step 3 — Create the record**: A new `MarketPlace` record is created with hashed password and status 1 (active).

4. **Step 4 — Set session**: `session('marketplace_user_id')` is set to the new user's ID, logging them in immediately.

5. **Step 5 — Send welcome email**: Calls `MailService::sendMailable()` with `MarketplaceWelcomeMail`. Failures are logged but don't block registration.

6. **Step 6 — Handle errors**: Validation errors are re-thrown for Laravel to handle. Other exceptions are caught and return an error notification.

### AJAX Availability Check Controller Logic (lines 438-456):
- `checkAvailability()` accepts POST requests with `field` and `value`
- For `email`: checks if email exists in market_places table
- For `number`: checks if phone exists in market_places table
- Returns JSON with error or success

### Frontend Registration Wizard (3-Step Alpine.js Component):

**Step 1 — Personal Information:**
- **Full Name**: Text input with validation icon binding
- **Email**: With AJAX availability check — `@input.debounce.500ms` calls `checkAvailability()` which POSTs to server and updates `errors.email`. Red error text displayed when taken.
- **Password**: With real-time strength checklist showing:
  - Min 8 characters (checkmark when met)
  - One uppercase letter
  - One lowercase letter
  - One number
  - One special character
  - Show/hide toggle for password visibility
- **Confirm Password**: With validation that it matches password
- **Phone Number**: With AJAX availability check (same as email)
- **Location**: Text input

**Step 2 — Professional Profile:**
- **Core Profession**: Dropdown with 40+ film industry roles
- **Experience (Months)**: Number input with real-time conversion to human-readable format (e.g., "8" → "8 months", "24" → "2 years"). Displays a "Converted" badge dynamically.
- **Bio**: Textarea for professional summary
- **Skills Manager**: Chip-style input where user types a skill and clicks "Add" (or presses Enter). Skills appear as removable chips. Comma-separated string is stored in a hidden input.
- **Portfolio URL**: Optional external link
- **Website URL**: Optional official website

**Step 3 — Finalize Account:**
- **Business Name**: Required
- **Business Type**: Dropdown (Individual, Studio, Production, Agency, Freelancer, Other). If "Other" is selected, a custom text input appears.
- **Terms Checkboxes**: Two required agreements:
  - Terms of Service & Privacy Policy (links open SweetAlert2 modals with AJAX-loaded content)
  - Marketplace Terms & Conditions (same modal pattern)
- **"Create Account" button**: Shows a SweetAlert2 loading spinner while form submits

**Navigation**: Next/Previous buttons between steps with validation gating (Next button is disabled if current step is invalid). A stepper progress bar at the top shows 3 steps with animated gradient fill.

## Step 10: Dashboard Shell (dashboard.blade.php)
**Route:** `GET /marketplace/dashboard` → `MarketPlaceController@dashboard()`
**Layout:** `@extends('layouts.app')`

### Controller Logic (lines 566-608):

1. **Authentication check**: If `session('marketplace_user_id')` is not set, redirects to login page.

2. **Fetch creator data**: Loads the marketplace profile with eager-loaded `galleries`, `services`, and `contacts` relationships.

3. **Fetch plans**: All `UserPlan` records.

4. **Fetch subscriptions**: All subscriptions for this creator, latest first. Also identifies the active subscription (where `end_date > now()` OR `end_date IS NULL`).

5. **Fetch transactions**: Deposit records where `marketplace_id` matches and has either a `plan_id` or detail JSON containing `marketplace_plan` type. Paginated at 10 per page.

6. **Backfill plan names**: For old deposits that only store plan_id in detail JSON (not as a relation), the method loads the actual plan records and manually sets the relation.

7. **Fetch messages**: All `MarketMessage` records for this creator, grouped by `user_id`, ordered by `created_at ASC`. This powers the messaging tab.

8. **Calculate unread count**: Count of messages where `sender_type = 'user'` AND `is_read = 0`.

### Frontend Alpine.js Architecture:

The dashboard shell uses a sophisticated Alpine.js component with:
- **`tab`**: Current active tab (syncs to `window.location.hash`)
- **`sidebarOpen`**: Mobile sidebar toggle state
- **`unreadCount`**: Real-time unread message count
- **`activeChat`**: Currently selected chat user ID (for messages tab)
- **`markMessagesRead()`**: Fires when messages tab is clicked — POSTs to `marketplace.messages.read` to mark all as read, then sets `unreadCount = 0`
- **`editService`**: State for the edit service modal (open, id, name, brief, img)
- **`planPurchase()`**: Spread operator imports Razorpay purchase functions from scripts.blade.php
- **`transactionInvoice()`**: Spread operator imports invoice modal functions

**Tab switching**: `x-init` validates the tab against valid options, then watches for changes to update the URL hash. `x-effect` manages mobile bottom navigation visibility (hides when in messaging chat view).

### What the page contains:

- "My Dashboard" title

- Navigation buttons for all 9 tabs: Dashboard, Profile, Gallery, Portfolio, Services, Messages, Contacts, Plans, Transactions

# PART D: CONTROLLER LOGIC (MarketPlaceController.php)

## Complete Method-by-Method Breakdown

### Method 1: `index(Request $request)` — Marketplace Homepage
**Route:** `GET /marketplace`
**Lines:** 26-103

**What it does:**
1. Reads query parameters: `type`, `location`, `search`
2. Builds two separate queries (featured + regular)
3. Featured query: `MarketPlace::where('status', 1)` AND (`is_featured = true` OR has active subscription with featured plan)
4. Regular query: `MarketPlace::where('status', 1)->where('is_featured', false)`
5. Applies optional filters to both queries
6. Limits: 8 featured (random), 24 regular (random)
7. Checks for logged-in creator session
8. Fetches gallery items and platform stats
9. Returns view with all data

### Method 2: `all(Request $request)` — All Profiles Page
**Route:** `GET /marketplace/all`
**Lines:** 108-168

**What it does:**
1. Reads query parameters: `type`, `search`, `filter`
2. Builds base query on active profiles
3. Applies type, featured, search filters as needed
4. Sorts by subscription count (featured first) then latest
5. Paginates 24 per page
6. AJAX support: returns JSON with rendered HTML for seamless filtering

### Method 3: `featured(Request $request)` — Featured Profiles Page
**Route:** `GET /marketplace/featured`
**Lines:** 173-196

**What it does:**
1. Queries active featured profiles (same featured logic)
2. Orders by latest, paginates 15 per page
3. Returns the featured view

### Method 4: `portfolio($slug)` — Public Creator Portfolio
**Route:** `GET /m/{slug}`
**Lines:** 201-218

# IMPLEMENTATION GUIDE — How to Use & Extend the Marketplace Module

This section is a **developer cookbook**. It explains how to set up, use, extend, and troubleshoot every piece of the marketplace module. Use this when you need to add new features, fix bugs, or understand the recommended patterns.

---

## 🚀 Quick Start — 5-Minute Setup

### Prerequisites
- Database tables migrated (see `database/migrations/` for `market_places`, `market_galleries`, `market_services`, `market_portfolios`, `market_messages`, `market_contacts`, `market_subscriptions`, `marketplace_ratings`)
- Razorpay credentials in `.env`: `RAZORPAY_KEY`, `RAZORPAY_SECRET`
- Storage (R2/S3) configured for image uploads

### Step-by-step
```php
// 1. Register a creator (POST /marketplace/register)
// Expects: name, email, password, password_confirmation, number, location,
//          type (role), years_of_experience, bio, skills, business_name,
//          business_type, terms_agreed, terms_conditions

// 2. Log in (POST /marketplace/login)
// Expects: email, password

// 3. Update profile (POST /marketplace/profile/update)
// Expects: Any + image/cover_image files
// This is session-based auth — no Laravel auth guard used
```

### Session Auth Pattern
```php
// The marketplace uses its own session auth, NOT Laravel's auth()
// To check if a creator is logged in:
$creatorId = session('marketplace_user_id');
$creator = MarketPlace::find($creatorId);

// To log in:
session(['marketplace_user_id' => $talent->id]);

// To log out:
session()->forget('marketplace_user_id');
```

## 🧩 How to Use Each Part (Developer Perspective)

### A) Public Pages Implementation

#### Marketplace Homepage — How to Customize

**Adding a new filter:**
```php
// In MarketPlaceController@index (around line 26):
// 1. Read your new param
$genre = $request->input('genre');

// 2. Apply to both featured and regular queries
if ($genre) {
    $featuredQuery->where('genre', $genre);
    $regularQuery->where('genre', $genre);
}

// 3. Add the dropdown to index.blade.php form
// 4. The auto-submit onchange will handle the rest
```

**Adding a new section to the homepage:**
1. Add your query to `MarketPlaceController@index` between steps 1G-1I
2. Pass data via `compact()`
3. Add Blade section to `index.blade.php` between the existing sections
4. Follow existing CSS patterns (gradient backgrounds, rounded-xl cards)

#### All Profiles Page — AJAX Pattern

The `all()` method is the primary **API for AJAX filtering**. Use this pattern when you need to filter data without page reload:

```php
// How to implement a new filter on the All Profiles page:

// 1. Controller (MarketPlaceController@all):
$experience = $request->input('experience');
if ($experience) {
    $query->where('years_of_experience', '>=', $experience);
}

// 2. Alpine.js component in all.blade.php — add a new state variable:
//    experience: null,
//    setExperience(val) { this.experience = val; this.fetchProfiles(); }

// 3. Add to buildFilterUrl() in the Alpine.js component:
//    params.set('experience', this.experience);
```

**How AJAX pagination works:**
```php
// The fetchProfiles() Alpine method manually adds ?page= to the URL
// But the pagination links at the bottom are standard <a href="?page=2">
// LINKS — these do a full page load, not AJAX
// To make them AJAX too, add @click.prevent="fetchPage(page)" to paginator links
```

#### Creator Portfolio — Subscription Gating Pattern

This is the most important security pattern. Reuse it anywhere premium content needs protection:

```php
// Standard gating pattern to copy-paste:
$hasSubscription = auth()->check() && auth()->user()->purchasedPlans()
    ->where('expired_date', '>', now())->exists();
$isOwner = session('marketplace_user_id') == $marketplace->id;
$canView = $hasSubscription || $isOwner;

// In Blade:
@if($canView)
    {{-- Show premium content --}}
@else
    <div @click="Swal.fire({ title: 'Premium Feature', ... })">
        {{-- Locked placeholder --}}
    </div>
@endif
```

**To add gating to a new feature:**
1. Add `$hasSubscription`, `$isOwner`, `$canView` to your controller
2. Pass them to the view
3. Wrap premium elements in `@if($canView)`
4. Add a SweetAlert2 popup for the locked state

#### Rating System — How to Implement Elsewhere

The rating component is reusable. To add ratings to any model:

```php
// 1. Create a ratings table (migration):
//    id, rateable_id, rateable_type, user_id, rating (1-5)

// 2. Add morphMany to the model:
public function ratings() {
    return $this->morphMany(Rating::class, 'rateable');
}

// 3. Use the same Alpine.js pattern from portfolio.blade.php:
//    x-data="ratingComponent({{ $model->avgRating }}, {{ $model->ratings->count() }})"
//    The stars, hover effect, breakdown bars can be copied verbatim
```

### B) Creator Dashboard Implementation

#### Dashboard Architecture Pattern

The dashboard is a **shell + section** architecture. Each tab is a separate Blade partial in `sections/`. To add a new tab:

```php
// 1. Create new section file: resources/views/frontend/marketplace/sections/mytab.blade.php
// 2. In dashboard.blade.php Alpine.js x-data, add your tab name to validTabs
// 3. Add nav button in the sidebar
// 4. Add @include in the content area, conditionally shown/hidden
// 5. In MarketPlaceController@dashboard, fetch and pass the new data
```

**State management tip:** Each tab's data is loaded ONCE when the dashboard loads. If your tab needs live data, use Alpine.js `x-init` to fire an AJAX request when the tab becomes active:

```js

```

### C) Razorpay Payment Flow

#### How to Add a New Paid Feature

The Razorpay flow has 3 parts. To add a new purchase type:

```php
// PART 1 — Initiate (Controller, e.g., buyPlan()):
// 1. Create a pending transaction
$deposit = Deposit::create([
    'marketplace_id' => $creatorId,
    'amount' => $plan->plan_price,
    'status' => 0, // pending
    'trx' => 'MP-' . uniqid(),
]);

// 2. If free, skip Razorpay
if ($plan->plan_price <= 0) {
    // Activate immediately
    return response()->json(['success' => true, 'redirect' => '/marketplace/dashboard']);
}

// 3. For paid, create Razorpay order
$razorpayOrder = Razorpay::order([
    'amount' => $plan->plan_price * 100, // paise
    'currency' => 'INR',
    'receipt' => $deposit->trx,
]);

return response()->json([
    'order_id' => $razorpayOrder['id'],
    'amount' => $plan->plan_price * 100,
    'key' => env('RAZORPAY_KEY'),
]);

// PART 2 — Frontend (in scripts.blade.php):
// The initiatePurchase() function opens Razorpay checkout modal.
// Copy the entire planPurchase() mixin — it handles all Razorpay lifecycle events.

// PART 3 — Verification (Controller, e.g., verifyPlanPayment()):
// 1. Verify signature: hash_equals(sha256(order_id + '|' + payment_id), secret)
// 2. Update deposit status to 1
// 3. Activate the subscription (create MarketSubscription record)
// 4. Return JSON success
```

## 🏗️ How to Extend the Module

### Adding a New Model

```php
// 1. Migration
Schema::create('market_reviews', function (Blueprint $table) {
    $table->id();
    $table->foreignId('marketplace_id')->constrained()->cascadeOnDelete();
    $table->text('review');
    $table->boolean('is_approved')->default(false);
    $table->timestamps();
});

// 2. Model
class MarketReview extends Model
{
    protected $fillable = ['marketplace_id', 'review', 'is_approved'];
    
    public function marketplace(): BelongsTo
    {
        return $this->belongsTo(MarketPlace::class);
    }
}

// 3. Relationship on MarketPlace
public function reviews(): HasMany
{
    return $this->hasMany(MarketReview::class);
}

// 4. Controller method
public function storeReview(Request $request, $id)
{
    $marketplace = MarketPlace::findOrFail($id);
    $marketplace->reviews()->create($request->validate([
        'review' => 'required|string|max:1000',
    ]));
    return back()->with('success', 'Review submitted for approval.');
}

// 5. Route (add to web.php)
Route::post('/marketplace/review/{id}', [MarketPlaceController::class, 'storeReview']);

// 6. View — add to portfolio.blade.php as a new section below the rating system
```

## 🧠 Architecture Decisions & Patterns

**Why session-based auth instead of Laravel auth?**
The marketplace has its own user model (MarketPlace) separate from the main platform's User model. Using a separate session key avoids conflicts and allows creators to be logged into both systems simultaneously.

**Why all logic in the controller (no service layer)?**
This was built as a self-contained module. The controller is the single source of truth for all marketplace business logic. If you extract it to a service layer, put all methods in `MarketplaceService` and call them from the controller.

**Why Blade sections instead of Livewire?**
The dashboard predates Livewire adoption in this project. Each tab is a separate include because the dashboard loads ALL tabs on initial page load then shows/hides them via Alpine.js. For very heavy tabs, consider lazy-loading via AJAX.

**Why Razorpay-specific (not abstract gateway)?**
Razorpay is the only payment processor used. To add a new gateway (Stripe, PayPal):
1. Create a new method `buyPlanStripe()` that creates a Stripe Checkout Session
2. Add a new verification endpoint `verifyStripePayment()`
3. Add a frontend button that redirects to Stripe instead of opening Razorpay modal
