1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
This document explains the scale-proof, high-concurrency upload architecture
implemented on the BINTEO platform. 

The primary goal of this architecture is to ensure that the platform can scale to
1,000+ concurrent users uploading large video files (up to 2 GB each) without 
exhausting resources on the central cPanel application server, causing timeouts,
or exceeding maximum storage and memory limitations.

3. THE CORE PROBLEM WITH TRADITIONAL SCALING
--------------------------------------------------------------------------------
In standard web configurations, upload bytes flow through the application server:
  User Browser (2 GB) -> cPanel/Laravel Web Server -> Bunny CDN

At a scale of 1,000 concurrent uploads:
*   Memory Consumption: 1,000 users × 2 GB = 2 Terabytes of data buffered in PHP.
*   Bandwidth Limits: The server must handle 2 TB of incoming traffic and 2 TB 
    of outgoing traffic simultaneously, exhausting network interfaces.
*   cPanel Crash: Apache/Nginx web workers saturate immediately, causing
    gateway timeouts (HTTP 504) and platform-wide outages.

4. SOLUTIONS IMPLEMENTED
--------------------------------------------------------------------------------
To support high concurrency, BINTEO implements a direct-to-destination pipeline:

### A. Android Mobile & Tablet Devices (Direct PUT Upload)
*   **Bypassing TUS & Proxy**: Mobile networks can terminate sustained chunk connections.
    Android devices bypass TUS and the cPanel proxy entirely.
*   **Direct Browser-to-Bunny**: The browser initiates a secure, direct PUT stream
    straight to Bunny CDN's media servers:
    Browser (Mobile) ───────────── Direct PUT Video Bytes ────────────► Bunny CDN
*   **Zero cPanel Burden**: Not a single byte of video data touches the cPanel 
    web server. cPanel handles only lightweight metadata authorization.

### B. Desktop & iOS Devices (Direct TUS Upload)
*   **Chunked TUS Upload**: Slices the video into 2MB chunks to ensure resumability.
*   **Direct Endpoint Routing**: The chunks are sent directly to Bunny CDN's TUS 
    endpoint (`https://video.bunnycdn.com/tusupload`) using CORS authorizations
    generated by Laravel.
*   **CORS Expose Headers**: Exposes TUS headers (like `Upload-Offset`) to enable
    resumable tracking directly inside the user's browser.

5. STEP-BY-STEP UPLOAD LIFECYCLE (CONCURRENT FLOW)
--------------------------------------------------------------------------------
Even if 1,000 users click "Publish" at the exact same moment:

1.  **Auth & Reservation (cPanel)**:
    *   The browser makes a tiny HTTP request to `/prepare-upload` (metadata only).
    *   Laravel registers a record in the database and requests a unique Video GUID
        from Bunny CDN.
    *   Laravel returns the Bunny Video GUID, direct upload URL, and signature.
    *   *cPanel overhead: Less than 1 KB of bandwidth & milliseconds of processing.*

2.  **Streaming (Bunny CDN)**:
    *   The browser opens a direct network pipe to Bunny Stream.
    *   All video data streams straight to Bunny CDN's global ingest network.
    *   *cPanel overhead: 0 bytes.*

3.  **Asynchronous Processing (Bunny Cloud)**:
    *   Bunny CDN receives and encodes the video on its own hardware.
    *   The browser checks the video progress periodically via `/status`.
    *   Once Bunny finishes encoding, Laravel updates the video record to 'ready'.

6. SCALABILITY VERIFICATION
--------------------------------------------------------------------------------
*   **Memory Footprint**: PHP handles only metadata, maintaining memory usage
    at low levels (< 20MB per request).
*   **Disk Space**: Temporary files are stored directly on Bunny CDN's storage
    cloud rather than cPanel local disks.
*   **Network Capacity**: Bunny CDN's massive globally distributed bandwidth handles
    incoming traffic, keeping the local server responsive for navigation,
    likes, and comments.

7. CONCLUSION
--------------------------------------------------------------------------------
By decoupling the data plane (large video bytes going to Bunny CDN) from the
control plane (user metadata and authentication remaining on Laravel), the system
is fully protected against performance degradation. BINTEO is optimized to 
handle high-volume concurrent media uploads safely.
