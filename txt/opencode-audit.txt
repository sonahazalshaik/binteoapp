════════════════════════════════════════════════════════════════════════════

┌──────────────────────────────────────────────────────────────────────────┐
│ [CRITICAL-1] Unsafe Dynamic Method Call in countBySegment              │
├──────────────────────────────────────────────────────────────────────────┤
│ File:     app/Services/Admin/UserService.php:553-556                    │
│ Route:    GET /admin/users/count-by-segment/{methodName}                │
│ Issue:    User::active()->{$methodName}()->count() — user-controlled   │
│           {methodName} is passed directly into PHP method invocation.   │
│           An attacker could call ANY method on User model (scopes,      │
│           where(), first(), all(), etc.) bypassing intended limits.     │
│ Risk:     HIGH - code injection via method reflection                   │
│ Fix:      Whitelist allowed method names (e.g., in_array($methodName,   │
│           ['regular', 'active', 'banned', 'creators']))                 │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐
│ [CRITICAL-2] Over-fetching ALL likes/comments/playlists on Video Index  │
├──────────────────────────────────────────────────────────────────────────┤
│ File:     app/Http/Controllers/Admin/VideoController.php:26             │
│ Issue:    with(['likes', 'allComments', 'playlists']) loads ALL related │
│           models into memory for every video on index, draft, featured, │
│           trending, premium, liked, public, private pages (lines 26-86) │
│ Risk:     HIGH - memory exhaustion when videos have 10K+ likes/comments │
│ Fix:      Replace with withCount(['likes', 'allComments'])              │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐

4. QUERY / PERFORMANCE ISSUES
════════════════════════════════════════════════════════════════════════════

[PERF-1] ManageUsersController/user detail — Extra 6 COUNT queries after
         loadCount (UserService:188-193). Instead of 1 batch query, 7
         individual queries. Fix: Use withCount with constraints.

[PERF-2] ManageUsersController/edit() — $user->subscribers->count() hydrates
         all subscribers into memory. Fix: $user->subscribers()->count()

[PERF-3] VideoController:show() — Loads ALL comments/likes for single video
         detail page. Should limit/paginate.

[PERF-4] Dashboard:total_watch_time — Full table scan on WatchHistory via
         sum('progress_seconds') as fallback. Expensive on large tables.

[PERF-5] Dashboard:getRecentUploads() — No status filtering, returns ALL
         videos. Add ->whereIn('status', ['published', 'public']).

[PERF-6] ManagePlaylist — Schema::hasColumn() checks for dynamic column
         detection. Code smell — run proper migrations instead.

[PERF-7] ManageVideoController — Large code overlap with VideoController.
         Dual-maintenance risk. Consider unifying into one controller.

7. INCONSISTENT PATTERNS
════════════════════════════════════════════════════════════════════════════

[PAT-1] VideoController:store() maps visibility to 'public'/'private'
         strings. ManageVideoController:store() stores visibility as raw
         0/1 integers. Same field, different formats = likely bugs.

[PAT-2] ChannelController:edit() hardcodes country list to 3 entries
         (India/US/UK) inline JSON. All other controllers read from
         resource_path('views/partials/country.json').

[PAT-3] ChannelService:updateChannel() modifies User model fields as
         side-effect of channel update. Overwrites user-set values.

[PAT-4] CommentService:updateComment() DELETES+RECREATES comment when
         type changes. Changes primary key, breaks all foreign references.

[PAT-5] DepositController:approve() uses /approve/{id} (route param) but
         reject() uses /reject (body param). Inconsistent API design.

[PAT-6] Store route named 'admin.videos.index_legacy' vs new routes using
         'admin.videos.index'. Two parallel video management systems.
