ADMIN_DOCUMENTATION - HOW EACH PAGE ACTUALLY WORKS
Project   : new-youtube (Binteo, YouTube-style platform)
Framework : Laravel 13 + Blade + Tailwind + Alpine.js + Chart.js + DataTables
File refs : file:line numbers point to the REAL code behind each screen.

CORE ARCHITECTURE PATTERNS (read this first - reused everywhere)
-----------------------------------------------------------------
1) CONTROLLER -> SERVICE -> MODEL:
   Every admin controller is thin. It resolves a service in its constructor
   (e.g. VideoController injects VideoService, DepositController injects
   GatewayService) and the service does ALL the real work. Views are rendered
   with compact('pageTitle', ...) - 'pageTitle' is shown in the page heading.

2) ROUTE FILES:
   - routes/web.php lines 278-511  -> modern admin group, middleware 'admin'
   - routes/web.php lines 514-524  -> admin auth routes, middleware 'guest:admin'
   - routes/admin-legacy.php       -> merged inside the admin group (web.php:506-508)
   Some old ad routes (advertiser.*, advertisement.*, advance.ads.*, campaign.*)
   are COMMENTED OUT in admin-legacy.php (lines 233-321).

3) MIDDLEWARE 'admin'  -> App\Http\Middleware\AdminMiddleware:
   checks auth()->guard('admin')->check(). If not logged in it stores
   session['url.intended'] and redirects to admin.login (so you return to the
   page you wanted after login). The 'guest:admin' middleware is the reverse
   for the login/register/forgot pages.

4) FLASH MESSAGES: every action ends with
       $notify[] = ['success', '...'];  return back()->withNotify($notify);
   'withNotify' is a custom macro that stores ['status'=>type,'message'=>text]
   in the session and the layout renders the toast.

5) HELPERS you will see everywhere:
   - gs('key') / gs()       -> cached GeneralSetting row values
   - notify($user, 'TEMPLATE_KEY', [...]) -> email/SMS/push notification dispatch
   - showAmount(), getAmount(), getTrx(), getPaginate(), fileUploader(),
     getFilePath(), getFileSize(), RequiredConfig::configured('...'), Status::* constants

6) USERS & ADMINS ARE SEPARATE MODELS:
   - Frontend users -> App\Models\User (flag columns: status active/ban, ev
     email verified, sv mobile verified, kv kyc, creator_status,
     monetization_status, advertiser_status; balance; views etc).
   - Admins -> App\Models\Admin. The 'admin' guard in config/auth.php uses
     provider 'admins' => Admin::class (session driver), independent from the
     'web' guard (User::class). That's why AdminAuthService can simultaneously
     log out the 'web' guard on admin login.
   - QUIRK: the (usually disabled) admin register form creates a User row with
     role='admin' and logs it in through guard('admin'), and the forgot-password
     flow (AdminAuthService.php:53) checks User->role === 'admin'; but the admin
     guard itself resolves the App\Models\Admin provider.

7) FILE STORAGE:
   - Avatars/thumbnails/KYC images -> R2 (Cloudflare) via ImageHelper::uploadToR2
   - Video/reel source files       -> uploaded locally first, then pushed to
     Bunny Stream CDN and transcoded to HLS by Bunny.
   - sitemap.xml/robots.txt/custom.css -> written straight to the public/root.
   - lang/*.json translation files   -> read/written directly on disk.

PHASE 1 - AUTHENTICATION & ACCOUNT (admin login, profile, notifications)

[admin/auth/login.blade.php]
- Route: GET  /admin/login   admin.login  (web.php:515)
         POST /admin/login   throttle:5,1 (web.php:516)
  Controller: Admin\AuthController.
- Controller flow: showLoginForm() (AuthController.php:20) just returns the view.
  login() (AuthController.php:26) validates [email|required|email, password]
  then calls AdminAuthService->login().
- How login works (AdminAuthService.php:16-34):
  1) Auth::guard('admin')->attempt($request->only('email','password'),
     remember). The 'admin' guard uses the session driver + Admin model
     provider (see architecture note 6), fully separate from the frontend
     'web' guard.
  2) If the frontend 'web' guard is also logged in, it is logged out FIRST so
     the two sessions never mix.
  3) $request->session()->regenerate() (prevents session fixation).
  4) Redirect = redirect()->intended(route('admin.dashboard')) - if the stored
     intended URL is NOT an /admin URL it falls back to the dashboard.
- Failure: returns back()->withErrors(['email' => 'auth.failed']).
- Brute force: protected by throttle:5,1 = 5 attempts per minute.

[admin/auth/register.blade.php]
- Route: GET/POST /admin/register (web.php:517-518), guest:admin + throttle.
- register() (AuthController.php:49) validates name/email|unique:users/
  password confirmed then AdminAuthService->register() (AdminAuthService.php:36):
  creates a User row with role='admin' (NOT an Admin record - see note 6),
  bcrypt password, fires the Laravel Registered event, and immediately logs in
  via the admin guard. Redirects to admin.dashboard. (Usually disabled.)

[admin/auth/forgot-password.blade.php]
- Route: GET  /admin/forgot-password admin.password.request (web.php:520)
         POST /admin/forgot-password admin.password.email throttle (web.php:521)
- sendResetLink() (AuthController.php:67) -> AdminAuthService->sendResetLink()
  (AdminAuthService.php:51): finds the user by email, VERIFIES role === 'admin'
  (normal users cannot reset through this page), then uses Laravel's
  Password::sendResetLink(['email'=>$email]) broker which emails the reset token.

[admin/auth/reset-password.blade.php]
- Route: GET  /admin/reset-password/{token} admin.password.reset (web.php:522)
         POST /admin/reset-password      admin.password.store throttle (web.php:523)
- The form collects email + token + new password (confirmed). resetPassword()
  (AuthController.php:85) -> AdminAuthService->resetPassword()
  (AdminAuthService.php:66) uses Password::reset() which validates the token
  belongs to the email, then the closure force-fills the hashed password,
  refreshes remember_token and fires PasswordReset. Redirects to admin.login.
- The token flows through the standard password_resets DB table.

[admin/profile.blade.php]
- Routes (admin-legacy.php:11-12): GET /admin/profile admin.profile,
  POST /admin/profile admin.profile.update.
- profile() (AdminController.php:40) -> AdminDashboardService->getAdminProfile()
  = auth()->guard('admin')->user(). Renders name/email/avatar.
- profileUpdate() (AdminController.php:46) validates name, email, image
  (new FileTypeValidate jpg/jpeg/png). If an image is uploaded it is stored
  with fileUploader($request->image, getFilePath('adminProfile'),
  getFileSize('adminProfile'), $old) which replaces the old file and returns the
  new relative path. Then updateAdminProfile() (AdminDashboardService.php:173)
  saves name+email. Redirect -> admin.profile with success toast.

[admin/password.blade.php]
- Routes (admin-legacy.php:13-14): GET/POST /admin/password admin.password.
- password() renders the form; passwordUpdate() (AdminController.php:76)
  validates old_password + password|min:5|confirmed, then
  updateAdminPassword() (AdminDashboardService.php:181):
     if !Hash::check(old_password, user->password) return false  -> error toast
     else Hash::make(new) + save -> success toast.

[admin/notifications.blade.php]
- Routes (admin-legacy.php:17-21): the bell icon opens this page.
  notifications (list), notification.read/{id}, notifications.read-all,
  notifications.delete-all, notifications.delete-single.
- notifications() (AdminController.php:93) -> getNotifications()
  (AdminDashboardService.php:195): returns paginated AdminNotification rows
  eager-loaded with user, plus hasUnread and hasNotification booleans.
- Marking one read (AdminDashboardService.php:204) sets is_read = YES and

PHASE 2 - APPLICATION SHELL (layouts, partials, reusable components)
================================================================================

[admin/layouts/app.blade.php]
- The master Blade @extends used by every modern admin page.
- Includes: head (fonts/CSS/Chart.js/DataTables), sidebar partial
  (admin.partials.sidenav), topbar (admin.partials.topnav), the breadcrumb
  partial, an @yield('content') slot, the admin.partials.cron_modal, and the
  JS stack. It renders any session 'notify' toast (the withNotify macro).
- It is plain Blade - each index page fills in the DataTables config + toolbar.

[admin/layouts/master.blade.php]
- Bare layout (head + centered content) used by auth & standalone pages.

[admin/partials/breadcrumb.blade.php]
- Renders the H1 page title ($pageTitle) + subtitle. Included by page headers.

[admin/partials/cron_modal.blade.php]
- A modal that shows the recommended crontab lines for the platform
  (queue:work, schedule:run, cron index URL). Opened from the dashboard when
  the cron endpoint hasn't reported a recent run.

[admin/partials/navbar.blade.php / sidenav.blade.php / topnav.blade.php]
- navbar: secondary strip with back-to-list links (used on create/edit pages).
- sidenav: the left menu. Groups map to the route names listed in this doc;
  active links highlighted by request()->routeIs(); permission-filtered.
- topnav: hamburger toggle, search, language switcher and the notification
  bell with an unread-count badge wired to admin.notifications.

[admin/components/header-toolbar.blade.php]
- Reusable list-page header: left = title + subtitle slot, right = action
  buttons slot (usually "Add/Deploy new" linking to create routes).
- Used on users, videos, banners, campaigns etc.

[admin/components/table-toolbar.blade.php]
- The toolbar above DataTables: search input + filter dropdowns + action
  buttons. Wires the search/filter values into the server-side table request
  and often exposes a "bulk actions" select whose value is posted together with
  the checked row ids to the module's bulk() controller method.

  POST /admin/videos/store (321) -> store() (143).
- store() validation (145-161): user exists, title, category exists, video file
  (mp4/mov/avi/wmv max ~1GB), thumb image, visibility in:0,1, pricing_tier
  free/premium/exclusive, price, captions (vtt/srt) optional.
- Save logic (163-212):
  - slug = Str::slug(title) . '-' . Str::random(5)
  - visibility '0' => 'public' else 'private'

  ->createVideo(title) gives a guid; then it uploads the local file bytes to
  https://video.bunnycdn.com/library/{lib}/videos/{guid} with the AccessKey
  header (timeout 3600s). On success video->update(bunny_id, bunny_status='processing').
- Finally dispatches App\Jobs\ProcessVideo::dispatch($video) (242) which
  processes/registers the video (thumbnail extract, transcript etc.).
