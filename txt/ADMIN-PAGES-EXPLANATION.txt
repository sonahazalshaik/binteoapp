================================================================================
ADMIN PANEL - PAGE-BY-PAGE PROCESS EXPLANATION
Project     : new-youtube (Laravel 13 YouTube-style platform)
Tech        : Blade + Tailwind + Alpine.js + Chart.js/ApexCharts + DataTables
Reading key : Each page = ~8-10 lines. WHAT it is -> WHAT it contains -> HOW the
              workflow runs -> WHO triggers it (controller / route).
The panel is divided PHASE BY PHASE (logical layers of the whole system).
================================================================================


================================================================================
PHASE 1 - AUTHENTICATION & ACCOUNT LAYER (admin auth + profile + notifications)
================================================================================

[admin/auth/login.blade.php]
- The admin login screen: centered card with username/e-mail + password,
  remember-me, and a submit button that posts to Admin AuthController@login.
- Flow: credentials validated (throttled against brute force), admin guard
  session created, then redirect to admin dashboard.
- Shows validation/reCAPTCHA errors via session flash messages; branded logo
  and dark/light theme styling shared with the app shell.
- Trigger: GET /admin/login renders it, POST /admin/login authenticates.
  (Route name basic: admin.login)

[admin/auth/register.blade.php]
- Optional self-registration form for new admin accounts (disabled in prod).
- Fields: name, username, email, password + confirmation; posts to Admin
  AuthController@register with full server-side validation rules.
- On success the account is created with proper role assignment and the admin
  is logged in and sent to the dashboard.
- Trigger: GET /admin/register (render), POST /admin/register (save).

[admin/auth/forgot-password.blade.php]
- "Forgot password" screen: single email field -> admin requests a reset link.
- Uses the same guard mechanics; a token email is dispatched and stored so the
  reset link can be validated later.
- Success/error feedback shown inline without leaving the page (Alpine state).
- Trigger: GET /admin/forgot-password, POST -> Admin AuthController.

[admin/auth/reset-password.blade.php]
- Password reset form reached from the emailed link; carries a signed token.
- Fields: new password + confirm; posts to Admin AuthController reset method
  which verifies the token then updates the hashed password.
- Flow ends with the admin being redirected to the login screen.
- Trigger: GET /admin/reset-password?token=..., POST -> reset.

[admin/profile.blade.php]
- The logged-in admin's account page under the "Profile" menu.
- Shows avatar upload/preview plus editable personal fields: name, username,
  email, phone, bio; posts back to AdminController (profile/update).
- Layout uses form-guard sections, image preview with Alpine, and success
  toasts; role permission badges may be rendered.
- Trigger: admin.profile route, POST -> profile update method.

[admin/password.blade.php]
- Dedicated "Change password" form: current password, new password, confirm.
- Always validates the CURRENT password against the stored hash before
  allowing an update; then re-hashes and stores.
- Success message and (optionally) logs the password-change event.
- Trigger: admin.password route, POST -> password update method.

[admin/notifications.blade.php]
- Central admin notification centre listing system events (new reports,
  withdrawals, KYC submissions, failed jobs, etc.).
- Renders notification list with read/unread state, icons, timestamps;
  supports mark-as-read, mark-all-read and item click-through to targets.
- Uses the NotificationController / AdminController notifications index which
  pulls the latest notifications for the admin.
- Trigger: routes on the shell topnav bell icon opening a slide-over / list.

[admin/components/notifications-dropdown.blade.php]
- The bell dropdown in the top navigation, live-loaded with unread items.
- Badge with unread count, "mark all read", and a link to the full
  notifications page; auto-refresh optional.
- Trigger: part of layouts/app topbar; data fetched via a small endpoint.

================================================================================
PHASE 2 - APPLICATION SHELL (master layout + shared partials/components)
================================================================================

[admin/layouts/app.blade.php]
- The main application layout wrapping every modern admin page.
- Sets up the HTML head (SEO, fonts, global CSS/JS assets) and the structure:
  sidebar navigation, top navbar, alert/toast mounting point, content slot.
- Declares shared Alpine stores/plugins (theme, sidebar collapse, live alerts)
  and includes the cron modal + global JS at the bottom.
- Every page extends this layout (e.g. @extends('admin.layouts.app')).

[admin/layouts/master.blade.php]
- A lighter/master Blade layout used by system-level pages (authentication,
  maintenance or standalone pages) that should not show the full sidebar.
- Provides just the page head, a centered viewport, and the content yield.
- Trigger: extended by login/register/forgot/reset and other bare pages.

[admin/partials/breadcrumb.blade.php]
- Shared breadcrumb block at the top of list pages (Dashboard / Module / Page).
- Auto-built from the current route name/segment or passed breadcrumbs array;
  renders the page H1 heading and a subtitle under it.
- Trigger: @include('admin.partials.breadcrumb') on many headers.

[admin/partials/cron_modal.blade.php]
- A modal that lists recommended cron jobs for the platform (queue worker,
  scheduler, cron index route) with copy-ready command lines.
- Common in shared-host setup: explains how to point crontab to php artisan
  schedule; opens from the cron/status or dashboard link.
- Trigger: included inside app layout; opened via Alpine state.

[admin/partials/navbar.blade.php]
- The bottom or secondary navigation strip of some pages; holds quick links
  back to list pages when editing/detailing a record.
- Trigger: @include from create/edit/view pages to navigate back easily.

[admin/partials/sidenav.blade.php]
- The left-hand sidebar: menu groups, icons, permission-filtered links,
  active-state highlighting, badge counts, collapsible submenus.
- User chip at the bottom with profile/logout; respects admin RBAC.
- Trigger: included in admin/layouts/app.blade.php.

[admin/partials/topnav.blade.php]
- Top header bar: hamburger (sidebar toggle), search box, theme/language
  toggles, and the notification bell with unread badge.
- Trigger: included in admin/layouts/app.blade.php.

[admin/components/header-toolbar.blade.php]
- Reusable toolbar for list pages: page title + subtitle on the left, action
  buttons (Create/Add/Refresh) on the right.
- Accepts slot-able buttons passed from each page; standardises headers.
- Trigger: rendered on most index pages (users, videos, banners, campaigns).

[admin/components/table-toolbar.blade.php]
- Table toolbar with search input, filter dropdowns, and action buttons above
  DataTables grids; wires search/filter events into the table.
- Often includes "bulk actions" selection (approve/block/delete all selected),
  which posts an array of checked IDs to the controller.
- Trigger: used with the datatable-container component (DataTables SSR).

PHASE 3 - DASHBOARD & GLOBAL REPORTING
================================================================================

[admin/dashboard.blade.php]
- The admin home: row of stat cards (users, videos, reels, earnings, deposits,
  withdrawals, pending items) each with trend arrows.
- Two chart canvases fed by AJAX endpoints (income vs expense, users/video
  growth) rendered with Chart.js; a live users table and quick actions.
- Includes the cron modal shortcut if scheduled commands are not running.
- Data: DashboardController@index aggregates counts/trends; refreshes via
  /admin/dashboard-chart JSON endpoints.

[admin/reports.blade.php]
- Top-level "Reports" landing aggregating several subreports into one page:
  users, videos, transactions, logins, watch history, active sessions.
- Usually a tabbed interface (Bootstrap-style tabs/Alpine) where each tab
  loads its own paginated table via the shared report controller.
- Quick export button per tab to CSV; dates filter at the top.
- Trigger: routes under admin.reports.* (Reports/AccountReportController).

[admin/videos/analytics.blade.php]
- Per-video analytics screen combining views, likes, comments, watch-time,
  and share counts for a chosen video.
- Line/bar charts for daily views and an engagement breakdown; player embed
  preview on the side.
- Trigger: admin.videos.analytics inside VideoController/@admin video module.

PHASE 6 - CONTENT MANAGEMENT: VIDEOS
================================================================================

[admin/videos/index.blade.php]
- Master video list: DataTables grid with cover thumbnail, title, channel,
  owner, views/likes, status, uploaded date.
- Toolbar filters: search, status, premium/video type; bulk select with
  actions (approve, reject, promote, delete).
- Approve/reject changes geolocation availability too (gs() premium rules).
- Trigger: admin.videos.list (VideoController@index).

[admin/videos/create.blade.php]
- Add video form: title, description, channel/user assignment, category,
  thumbnail upload, video file / HLS stream URL, visibility, comments toggle.
- Server-side validation on submit; on save the file is queued for
  processing via the ProcessVideo job.
- Trigger: admin.videos.create (VideoController@create/store).

[admin/videos/edit.blade.php]
- Edit existing video: reuse of create form sections pre-filled; can swap the
  source file, thumbnail, category, premium/monetisation status.
- Resaving flags the video for re-processing if the file changed.
- Trigger: admin.videos.edit (VideoController@update).

[admin/videos/view.blade.php]
- Video detail/view: embedded player + metadata panel, owner/channel info,
  status badges, and action buttons (approve/reject/block/edit/delete).
- Sub-tabs listing this video's comments, likes, watch-later and playlist
  memberships (links to interactions pages).
- Trigger: admin.videos.view (VideoController@view).

[admin/videos/not_interested.blade.php]
- A "not interested" feedback log: users who marked the video as not
  interested with reasons, used to tune recommendations.
- Table of video + user + timestamp; filterable, clearable.
- Trigger: admin.videos.notInterested.

[admin/videos/interactions/comments.blade.php]
- All comments left on a chosen video with user, text, report/like counts;
  inline toggle to hide/delete specific comments.
- Trigger: admin.videos.interactions.comments (nested under video detail).

[admin/videos/interactions/likes.blade.php]
- Likes received by the video: user list with timestamps, total count header.
- Trigger: admin.videos.interactions.likes.

[admin/videos/interactions/playlists.blade.php]
- Which playlists contain this video: playlist title, owner, added date.
- Trigger: admin.videos.interactions.playlists.

[admin/videos/interactions/watch_later.blade.php]
- Users who saved the video to "watch later" with date saved.
- Trigger: admin.videos.interactions.watchLater.
