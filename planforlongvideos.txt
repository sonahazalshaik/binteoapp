If you stay on Bunny Stream's free tier, long videos take forever because Bunny treats every
single output resolution and extra feature as an independent encoding job. If your library
is configured with 240p, 360p, 480p, 720p, 1080p, and MP4 fallback enabled, a single
45-minute upload triggers 5–6 separate transcoding passes on a shared, low-priority queue.
You can cut processing times drastically without paying for premium encoding by combining
dashboard-level pipeline trimming, UX trickery, and client-side optimization.
1. Trim Enabled Resolutions (Biggest Impact)
In your Bunny Dashboard, go to Stream \rightarrow Video Library \rightarrow Encoding:
● Disable unnecessary resolutions: Turn off 240p, 1440p (2K), and 2160p (4K) if they are
active.
● Run a lean 3-resolution profile: Stick to 360p (mobile/poor network), 720p, and
1080p. Halving your enabled resolutions directly cuts queue compute time by ~50%.
● Disable "MP4 Fallback": MP4 fallback creates full standalone .mp4 downloads
alongside HLS playlists. If you only stream via the web player, disabling this eliminates
another entire transcode cycle.
2. Enable "Early-Play" in Bunny
Under Stream \rightarrow Video Library \rightarrow Encoding, turn on Enable Early-Play.
● How it works: Instead of making users wait for all resolutions (1080p, 720p, etc.) to
complete before the video becomes playable, Bunny allows the video to be streamed
immediately using the source file or the first completed lower rendition while the rest finish
in the background.
● Verification: Test this by uploading a 10-minute video via the dashboard; the video status
will shift to playable almost immediately rather than remaining in a prolonged "Processing"
state.
3. Client-Side Constraints Before Upload
Since you already do pre-editing in the browser for reels, apply similar upfront rules before
users upload long videos:
● Enforce an input profile: If a user uploads a 4K 60fps raw phone recording with a
massive bitrate (e.g., 60–80 Mbps), Bunny has to decode gigabytes of raw frames on a
shared CPU.
● Client-side checks: Use JavaScript (<video> metadata tag) to inspect duration, file size,
and resolution before starting the TUS upload. Capping long uploads to a maximum
source resolution of 1080p at 30/60fps significantly cuts processing time on Bunny's
servers.
● Fast-start optimization: Ensure uploaded .mp4 files have the moov atom at the
beginning (streaming-optimized), which lets Bunny start reading the stream without
reading the entire file tail first.
4. Implement YouTube's Async UI in Laravel
YouTube rarely lets users wait on an upload screen until 4K or 1080p finishes processing.
Replicate this lifecycle in Laravel:
[User Uploads via TUS]
↓
[Laravel creates Video record with status: "processing"]
↓
[Publish/Listing allowed as "Unlisted" or "Draft"]
↓
[Bunny Webhook: Video Transcoded]
↓
[Update Video status: "ready" -> Mark as "Public" or notify user]
1. Direct TUS Upload: User uploads directly to Bunny Stream using Tus-js-client (no video
touches your Laravel backend).
2. Instant Feedback: As soon as TUS finishes, redirect the creator to their video details
page (title, description, tags, thumbnail) and show a progress badge: "SD processing
complete. HD processing in background."
3. Webhook Handling: Register a Bunny webhook endpoint in your routes/api.php
(/api/webhooks/bunny). When Bunny sends the Video Transcoded (status 3/4) payload,
fire a Laravel event to flip the video to published and push a real-time notification to the
creator via Pusher/Reverb.
