══════════════════════════════════════════════════════════════
  ⚠  DO'S & DON'TS
══════════════════════════════════════════════════════════════

  ✅ DO's:
  • Use Resources to transform DB data for Flutter app.
  • Map DB column names to clean API keys in Resources.
  • Use Sanctum for API token authentication.
  • Return consistent JSON structure (status/message/data).
  • Use whenLoaded() in Resources for eager-loaded relations.

  ❌ DON'Ts:
  • DON'T return Eloquent models directly from API controllers
    — always use Resources to control the response shape.
  • DON'T expose sensitive fields (password, tokens) in Resources.
  • DON'T change API response format — Flutter app depends on it.
  • DON'T remove Sanctum — it's the auth layer for mobile.
  • DON'T mix web session auth with API token auth.
